# Sanjeevani backend — locked decisions

This file records decisions made during the contract-and-mocks phase so future
sessions don't re-litigate them. Read this before changing conventions.

## Phase

This is **contract-and-mocks only**. No database, no ORM, no LLM/agent logic, no
external service calls. All data lives in `app/mocks/fixtures/*.json`, loaded
once into an in-memory `Store` (`app/mocks/loader.py`) at process start. State
mutated by POST endpoints (approvals, settlements, negotiation outcomes) lives
only for the lifetime of the running process.

Do not add a database, SQLAlchemy models, or real LLM/agent calls in this phase
without an explicit decision to move phases. When that phase starts, the store's
shape (dicts of pydantic models keyed by id) should map close to 1:1 onto
SQLAlchemy models — that's why it's built this way now.

## Conventions (follow everywhere, no exceptions)

- **Money**: every money field is an **integer number of paise**, named with a
  `_paise` suffix. Never a float. Use `app.schemas.money.format_inr(paise)` for
  full Indian-grouped display (`"₹62,00,000"`) and `format_inr_short(paise)` for
  short form (`"₹62.0L"`, `"₹6.2Cr"`). Every money value that ships with a display
  string alongside it (e.g. `total_paise` + `total_display`) must be generated by
  calling one of these helpers on the paise value — never hand-write the display
  string separately, they will drift. (This happened once already in
  `metrics_demo.json` and was caught by `tests/test_money.py`'s fixture
  consistency tests — keep those tests, they're the guardrail.)
- **Timestamps**: timezone-aware UTC ISO-8601, field suffix `_at`. Use
  `app.schemas.money.utc_now_iso()`.
- **IDs**: string UUIDv4, everywhere. No integer/serial IDs.
- **Envelopes**: every domain object response includes `id`, `created_at`,
  `updated_at` (see `app.schemas.common.Envelope`).
- **Enums**: UPPER_SNAKE, defined once in `app/schemas/enums.py`. Don't redefine
  or duplicate an enum value inline in another schema file.
- **Future DB**: the eventual database is Neon Postgres via SQLAlchemy, multi-writer.
  Don't write anything in this phase that assumes SQLite semantics or a
  single-writer process (e.g. don't rely on file locks, don't assume in-process
  mutation is the only way data changes).

## API shape rules

- Every response model lives in `app/schemas/`, split by domain. Routers never
  define inline response shapes — import from schemas.
- Every router file maps to one domain and is included in `app/main.py`.
- Idempotency: any POST that takes an `idempotency_key` must cache its full
  response by that key and replay the identical response on a repeat call,
  never a duplicate side effect or an error. See `app/routers/approvals.py` for
  the pattern (`store.approval_idempotency` dict).
- Auth: `X-API-Key` header, checked only when `REQUIRE_API_KEY=true`. Off by
  default in dev so teammates can hit endpoints immediately.
- Path spelling is intentionally inconsistent between `/api/v1/settlements/...`
  (plural, execute) and `/api/v1/settlement/...` (singular, batch/confirm) —
  this matches the locked contract in CONTRACT.md exactly. Do not "fix" this
  without updating CONTRACT.md and telling the frontend/voice teams first.

## WebSocket `/api/v1/live`

- Single global `LiveFeedManager` (`app/ws_manager.py`) holds the connection set
  and a 50-event ring buffer. On connect, the last 50 events are replayed, then
  the connection receives live broadcasts.
- Every event type is broadcast through `live_feed.broadcast(...)` — never send
  raw dicts from a router; always go through this so the ring buffer and all
  connected clients stay consistent.
- Heartbeat (`HEARTBEAT` event, no payload) fires every 20s regardless of mock
  mode. The scripted disruption replay (every 45s) only runs when
  `MOCK_LIVE_REPLAY=true`.

## Adding a new fixture-backed endpoint

1. Define the response schema in `app/schemas/<domain>.py`.
2. Add/extend a fixture JSON file in `app/mocks/fixtures/`.
3. Load and validate it in `app/mocks/loader.py` (`Store.__init__`) — fixtures
   must validate against their pydantic model at startup, this is intentional
   (catches shape drift immediately instead of at request time).
4. Add the route to the matching `app/routers/<domain>.py` file, or create one.
5. Update `CONTRACT.md` with the new endpoint/example.
6. Add a case to `tests/test_contract.py`.
